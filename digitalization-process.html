Project

Digitalization Process

A workflow and digitalization project focused on replacing manual evaluation and reporting steps with a more structured, traceable and scalable process.

Overview

The project was initiated to improve an existing evaluation and reporting process by replacing parts of the previous manual workflow with a more centralized and digitally supported structure.

Key goals included reducing manual work, increasing data quality, improving traceability, enabling central data storage and making evaluations faster overall.

Problem

The existing process relied heavily on manual handling, fragmented files and limited automation, which made evaluation and reporting more time-consuming and less transparent.

Goal

The aim was to design a clearer target workflow supported by a stable data structure, automated analysis functions and a more user-friendly reporting process.

My Role

I was involved in GUI development and in the broader coordination and structuring of the project context, helping translate requirements into a workable concept.

Project Scope

  • Analysis of the existing setup, including macros, add-ins and Excel files.
  • Definition of requirements for heatmaps, time series views and reporting outputs.
  • Work on data management structures and import processes.
  • Support for a Python-based backend and GUI concept using PySide6.
  • Consideration of reporting outputs such as PDF and PowerPoint export.

System Structure

The project was structured across several connected areas: project management, functional requirements, data management, Python backend, user interface, reporting, testing and introduction.

Planned components included database access, climate index calculation, heatmap and time series functions, benchmark logic, reporting modules and export options for presentation-ready outputs.

Technical Direction

The documentation shows a clear technical direction: Git as a shared development platform, Python-based functionality and a desktop GUI built with PySide6 to make the application accessible and usable for non-technical users.

Milestones

The project was organized around milestones such as approved requirements, a working data platform, implemented analysis functions, finished report generation and final go-live preparation.

Open Questions

Remaining questions included where created files should be stored and how visual outputs should be handled in the future, for example through Power BI or static graphics.

What I learned

This project strengthened my understanding of how digitalization depends not only on technical implementation, but also on process clarity, requirement definition and coordination across stakeholders and outputs.

It also showed me how closely data structures, interface decisions and reporting logic are connected when building solutions that need to work reliably in everyday practice.
