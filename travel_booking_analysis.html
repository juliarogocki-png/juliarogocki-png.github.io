Booking Behaviour by Device Type

A focused exploratory data analysis of hotel-search and booking behaviour, examining whether desktop and mobile users differ in booking conversion, travel distance and requested stay length.

Focus: Exploratory data analysis, behavioural comparison, data visualization

Role: Data preparation, statistical exploration, visualization and interpretation

Tools: Python, pandas, seaborn, matplotlib

Back to projects

Project context

This project uses booking-search data to investigate how the device used during a hotel search relates to user behaviour. The analysis is deliberately descriptive: it identifies visible patterns and differences without claiming that device type alone causes a booking outcome.

  • Dataset: Hotel-search and booking records
  • Unit of analysis: Individual search records
  • Output: Three focused static visualizations
  • Approach: Group comparison and distribution analysis

Research question

Do desktop and mobile users show different booking behaviour, particularly in booking conversion, travel distance and requested stay length?

The analysis evaluates three connected aspects of the booking journey. First, it compares the booking rate between device groups. Second, it examines whether desktop and mobile searches differ in the distance between the traveller's origin and the destination. Third, it explores the distribution of requested stay length.

The guiding assumption is not that one device is inherently better than the other. Instead, the goal is to identify behavioural signals that could inform UX decisions, such as where mobile booking flows may need additional reassurance or where desktop users may be more likely to complete a reservation.

Key visualizations

Each chart addresses a specific part of the research question. Together they show the conversion gap, the travel-distance distribution and the shape of stay-length data.

Booking rate by device type

The chart provides the clearest answer to the conversion part of the question: bookings occur more frequently among desktop records in this dataset. The difference is descriptive and should not be interpreted as a causal device effect without further controls for factors such as market, trip type, user history or traffic source.

Travel distance by device type

The central distributions overlap considerably, but desktop searches extend to a higher upper whisker than mobile searches. The many outliers indicate that a relatively small number of searches involve very long distances, so the median and interquartile range are more informative than the extreme values alone.

Stay-length distribution

The density plot suggests that desktop and mobile users have broadly similar stay-length patterns. Most searches concern short stays, whereas longer stays occur less often and create a pronounced right-skew. The overlap means stay length alone does not clearly separate the two device groups.

Code & implementation

The analysis is implemented as a reproducible Python workflow. It loads the CSV data, derives stay length from search dates, calculates grouped booking rates and saves each visualization in a consistent portfolio style.

Data preparation

Search dates are converted to datetime values before the requested stay length is calculated in days. 

df["srch_ci"] = pd.to_datetime(df["srch_ci"], errors="coerce")
df["srch_co"] = pd.to_datetime(df["srch_co"], errors="coerce")

df["stay_length"] = (
    df["srch_co"] - df["srch_ci"]
).dt.days

Booking-rate comparison

The booking rate is calculated as the mean of the binary booking indicator for each device group. 

booking = (
    df.groupby("is_mobile")["is_booking"]
    .mean()
    .reset_index()
)

booking["device"] = booking["is_mobile"].map({
    0: "Desktop",
    1: "Mobile"
})
