Device Type & Booking Conversion

An exploratory analysis of 99,496 hotel-search sessions examining whether desktop and mobile users show different booking-conversion patterns after accounting for search distance and requested stay length.

Focus: Booking conversion and device comparison
Role: Data cleaning, feature engineering, analysis and interpretation
Methods: EDA · data visualization · logistic regression
Tools: Python · pandas · seaborn · matplotlib · scikit-learn

Project context

From hotel search to booking

Travel products are often used across devices. This analysis asks whether booking conversion differs between desktop and mobile search sessions—and whether observable search context helps explain that pattern.

The project combines descriptive analysis with an exploratory logistic regression model. It identifies associations in the dataset; it does not demonstrate that device type causes a conversion difference.

  • Outcome: booking completed or not completed
  • Main comparison: desktop versus mobile sessions
  • Context variables: search distance and stay length
  • Final sample: 99,496 cleaned search sessions

Data source: Expedia Hotel Recommendations on Kaggle

Research question

Are booking rates associated with device type?

Do hotel-search sessions on desktop and mobile devices have different booking-conversion rates, and does the observed pattern remain when search distance and requested stay length are considered together?

I approached the question in three steps. First, I compared the observed booking rates for desktop and mobile sessions. Second, I examined whether the search contexts differed visibly by device, using origin-to-destination distance and requested stay length. Finally, I fitted a logistic regression model to estimate the device association while including both contextual variables.

This sequence keeps the analysis interpretable: it separates what is visible in the raw data from what remains in an adjusted, exploratory model.

Data preparation

From raw records to an analysis-ready sample

The original 100,000-session sample required preparation before comparison and modelling. Each choice was documented to make the workflow transparent.

  • Device variable: Converted is_mobile into readable Desktop and Mobile categories.
  • Missing distance values: Replaced 36,085 missing origin-to-destination distances with the sample median.
  • Missing dates: Removed 122 sessions with missing check-in or check-out dates.
  • Travel-distance extremes: Capped values using the 1.5 × IQR rule; the final upper cap was approximately 3,001 dataset units.
  • Stay length: Calculated from check-in and check-out dates, removed zero or negative stays, and restricted the display and analysis range to 1–30 days.
  • Final sample: 99,496 search sessions, with no remaining missing values in the analysis variables.

Descriptive findings

Desktop sessions show higher observed conversion

In the cleaned analysis sample, 8.3% of desktop sessions resulted in a booking, compared with 6.1% of mobile sessions—a difference of 2.2 percentage points.

Key finding

The clearest visible difference is in booking conversion.

Search distance and stay length provide useful context, but neither appears to separate desktop and mobile sessions as clearly as the conversion-rate comparison does.

Descriptive interpretation: The conversion-rate difference is more pronounced than the visible differences in search context. This supports examining device type in an adjusted model, while avoiding the assumption that device alone explains conversion.

Exploratory regression

The adjusted pattern remains negative for mobile sessions

A logistic regression model estimated booking status from device type, origin-to-destination distance and stay length. All predictors were standardised before fitting the model so their coefficients can be compared on a common scale.

Predictor Coefficient Odds ratio Direction
Mobile indicator -0.1136 0.8926 Lower adjusted booking odds
Search distance -0.0269 0.9735 Slightly lower adjusted booking odds
Stay length -0.6219 0.5369 Lower adjusted booking odds

Model note: N = 99,496 sessions. Predictors were standardised with StandardScaler before modelling. Therefore, odds ratios represent a one-standard-deviation change in each predictor. The reported 91.97% training accuracy should not be treated as proof of strong predictive performance because bookings are the less frequent outcome in this dataset.

How to interpret the model

After including search distance and stay length, the mobile indicator still has a negative coefficient (β = -0.1136; standardised OR = 0.8926). Within this exploratory model, the observed desktop–mobile conversion pattern is therefore not fully explained by the two included context variables.

Stay length has the largest coefficient magnitude of the three predictors (β = -0.6219). This suggests that it is the strongest association among the modelled variables. It does not establish that longer stays cause lower conversion: unmeasured factors, such as price, trip purpose, destination, availability and user intent, may affect the result.

Workflow transparency

Show the code behind the result

This excerpt creates the conversion-rate figure, including a consistent device order, session counts and an annotation for the percentage-point difference. The complete modular workflow is available on GitHub.

visualizations.py 
import numpy as np
import matplotlib.pyplot as plt

device_order = ["Desktop", "Mobile"]

booking_summary = (
    df.groupby("device")["is_booking"]
      .agg(booking_rate="mean", sessions="count")
      .reindex(device_order)
)

difference_pp = (
    booking_summary.loc["Desktop", "booking_rate"]
    - booking_summary.loc["Mobile", "booking_rate"]
) * 100

fig, ax = plt.subplots(figsize=(8, 5), facecolor="#f7f6f2")
ax.set_facecolor("#f7f6f2")

bars = ax.bar(
    booking_summary.index,
    booking_summary["booking_rate"],
    width=0.54,
    color=["#a95f76", "#d98fa1"]
)

for bar, rate, sessions in zip(
    bars,
    booking_summary["booking_rate"],
    booking_summary["sessions"]
):
    ax.text(
        bar.get_x() + bar.get_width() / 2,
        rate + 0.003,
        f"{rate:.1%}",
        ha="center",
        va="bottom",
        fontweight="700"
    )

ax.text(
    0.5,
    0.096,
    f"+{difference_pp:.1f} percentage points on desktop",
    ha="center",
    va="center"
)

ax.set_title("Observed Booking Rate by Device Type")
ax.set_ylabel("Booking rate")
ax.yaxis.set_major_formatter(
    plt.FuncFormatter(lambda value, _: f"{value:.0%}")
)
ax.set_ylim(0, 0.105)

plt.tight_layout()
plt.savefig(
    "visuals/booking_rate.png",
    dpi=300,
    facecolor="#f7f6f2",
    bbox_inches="tight"
)
plt.close(fig)

Limitations

What this analysis can—and cannot—say

The analysis is designed for transparent exploration, not causal inference or production prediction.

  • Observational data: Device groups were not randomly assigned, so differences may reflect user intent or other confounding factors.
  • Limited features: The model does not include price, discounts, hotel quality, availability, destination appeal, prior behaviour or checkout-flow interactions.
  • Missing-distance treatment: Median imputation preserves sample size but reduces variation in the distance variable.
  • Model evaluation: Training accuracy is not enough for evaluating a booking model with an imbalanced outcome. A next iteration should use a train/test split and report precision, recall, ROC-AUC or precision-recall AUC.

Business approach

Turn the finding into a mobile-conversion research plan

The observed gap is a signal for further product investigation—not a reason to assume that mobile users are inherently less likely to book.

A travel product team could treat the 2.2-percentage-point gap as a prioritisation cue: investigate whether mobile searchers face friction in the booking journey, or whether they are using mobile primarily for early trip research and switching devices before purchase.

  • Diagnose the funnel: Compare mobile and desktop drop-off between search results, hotel detail pages, room selection and checkout.
  • Combine quantitative and qualitative UX research: Review session recordings and conduct moderated usability tests focused on mobile filtering, date selection, price clarity and payment entry.
  • Support cross-device intent: Test save-and-resume features, email reminders, wishlists or deep links that make it easy to continue a mobile search on another device.
  • Test targeted improvements: Run controlled experiments for simplified mobile checkout, clearer total-price communication and reduced form friction. Evaluate conversion together with completion rate, error rate and user confidence.

Portfolio takeaway: The project moves from a descriptive pattern to a responsible product hypothesis: understand the mobile booking journey before deciding which design intervention to test.
